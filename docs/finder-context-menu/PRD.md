# ClipStats 访达右键增强 · 产品需求文档（PRD）

> 状态：**待评审（v2，已吸收两轮评审意见）**
> 目标版本：v2.1.0（P0）
> 关联文档：[TECH.md](./TECH.md) · [REVIEW-NOTES.md](./REVIEW-NOTES.md)
> 技术前提：Finder Sync 扩展已于 2026-11-19 在 macOS 27 / M1 / ad-hoc 签名下实测跑通（菜单、点击、写文件、剪贴板全部可用）

**v2 相对 v1 的主要变化**（评审驱动）：
1. P0 菜单收敛为 **4 项**：打开类在前、创建类收尾；不重复系统自带能力。
2. 把「新建文件…」面板**提到 P0**，解决「未命名 2.md 还要手动改名」的痛点。
3. 新建类型从 5 个并列收敛为「快捷新建（1 个类型）+ 面板（5 个类型）」。
4. 复制路径 / 复制文件名**整项砍掉**：系统 `⌥⌘C` 与 `⌘C` 已经覆盖，我们不重复造。
5. 明确「不做自动激活访达 / 自动选中新文件」（用户实测反馈：每次弹窗很烦）。
6. 补齐失败反馈、错误文案表、可访问性与 macOS 15 的一键启用。

## 0. 一页结论

| 项 | 结论 |
| --- | --- |
| 做什么 | 访达右键里加一个 `ClipStats` 二级菜单：在终端或编辑器中打开 / 新建文件 |
| 给谁用 | 自己日常 + GitHub 上的中文程序员受众 |
| P0 菜单 | 4 项，见 §5.1 |
| 不做 | 文件管理器、超级右键全家桶、App Store、自动选中/激活访达、彻底删除 |
| 成功标准 | 常用的「在终端中打开」2 次点击内完成；「新建并开始写」不需要再改名 |
| 核心风险 | ad-hoc 分发门槛、macOS 15 无图形开关、TCC 首次授权、扩展常驻内存 |

## 1. 背景

ClipStats 现在的定位是「菜单栏系统小工具」：状态栏指标 + 剪贴板历史 + 运行中 App 管理 + 离线翻译，解决「看一眼 / 找回来」。但**没有覆盖「在文件系统里干活」的入口**。

程序员日常在访达里的高频动作都很别扭：

| 想做的事 | 原生体验 |
| --- | --- |
| 当前文件夹建一个 `.md` | 只能新建文件夹，文件要靠终端或编辑器另存 |
| 在当前文件夹开终端 | 拖拽文件夹进终端，或先配好「服务」 |
| 用 Cursor / VS Code 打开项目 | 原生「打开方式」列表又长又慢 |

动机是**缩短「想到 → 文件已就位」的路径**，不是堆功能。

---

## 2. 目标用户与场景

**主用户**：作者本人（写代码，经常在桌面/项目目录临时建文件）
**次用户**：从 GitHub 下载的技术用户（会看 README，能跑一条命令）

P0 必须覆盖的场景（按频率排序）：

1. 文件夹上右键 → **在终端中打开**（每天几次）
3. 文件夹或文件上右键 → **在 Cursor/VS Code 中打开**
4. 空白处右键 → **新建 Markdown 文件**（临时笔记，允许叫「未命名」）
5. 空白处右键 → **新建文件…**（要正经命名时用，回车即建）

## 3. 竞品与定位

| 产品 | 特点 | 我们的取舍 |
| --- | --- | --- |
| 超级右键（RightMenuMaster） | 新建/模板/二维码/图标/压缩，功能极全 | 不学。功能越多维护成本越高，且闭源 |
| OpenInTerminal | 只做「在终端/编辑器打开」 | 参考它的目录监听与菜单结构 |
| iTerm / 编辑器自带右键 | 各管一段 | 我们做统一入口 |

**差异化**：ClipStats 是「已经常驻菜单栏的工具，顺手把文件操作也管了」，所以坚持**少而准**——每个菜单项都必须有每周多次的真实场景。

## 4. 功能范围

### 4.1 P0（v2.1.0）

| 功能 | 说明 |
| --- | --- |
| 在终端中打开 | 以目标目录为 cwd 打开终端；默认「终端.app」 |
| 在「默认编辑器」中打开 | 自动检测 Cursor / VS Code / Zed，检测到才显示；标题带应用名 |
| 新建 Markdown 文件 | 一键建 `未命名.md`（重名递增），不弹任何窗口、不抢焦点 |
| 新建文件…（面板） | 主 App 弹出小面板：文件名 + 类型（Markdown/文本/JSON/Python/Shell）+ 回车即建；记住上次选择 |
| 结果反馈 | 成功：状态栏闪一下 + HUD 显示真实文件名；失败：HUD 显示具体原因 |
| 设置页「集成」分区 | 扩展状态检测、一键启用（含 macOS 15 的 pluginkit）、授权引导、重新加载访达 |

### 4.2 P1（v2.2.0）

| 功能 | 说明 |
| --- | --- |
| 菜单项开关 | 逐项关闭，避免菜单变长（配置通过扩展容器内的 JSON 下发） |
| 默认编辑器 / 默认终端可配置 | 不止自动检测 |
| 快捷新建的默认类型可配置 | P0 固定 Markdown |
| 模板 | `~/Library/Application Support/ClipStats/Templates/`，面板里出现「从模板新建」 |
| 计算 SHA256 | 选中文件后计算并写入剪贴板，大文件有上限提示 |
| 菜单项本地化 | `NSLocalizedString` + 英文 `.strings` |

### 4.3 明确不做

| 不做 | 原因 |
| --- | --- |
| 自动激活访达 / 自动选中新文件 | **实测反馈：每次弹访达窗口很烦**。文件本来就会出现在列表里 |
| 复制路径 / 复制文件名 | **系统已有 `⌥⌘C`（拷贝路径）与 `⌘C`**，不做系统自带的能力 |
| 替代 Finder（剪切/移动/批量重命名） | 与工具定位冲突，出错代价高 |
| 上架 App Store | 需整体沙盒化，与系统指标读取冲突 |
| 彻底删除（绕过废纸篓） | 不可逆、与「轻量可审计」定位冲突，且没有测试资源 |
| 压缩 / 隐藏文件 / 图标染色 | 低频，属「超级右键」范围 |
| 菜单项自定义图标 | FinderSync 对图标支持有限，收益低 |
| 让扩展直接弹 App 内 UI | appex 里 `NSApp` 不可用，技术不允许 |

## 5. 交互设计

### 5.1 菜单结构（P0，扁平 4 项）

```
ClipStats  ▸
  在终端中打开
  由 Cursor 打开            ← 已安装才显示
  由 VS Code 打开           ← 已安装才显示
  由 WebStorm 打开          ← 已安装才显示
  …（编辑器按已安装情况逐项列出）
  ─────────────
  新建 Markdown 文件
  新建文件…                  ← 弹面板，可选路径与类型
```

编辑器检测范围（**装了几个就列几项**，最多 16 项）：

| 类别 | 覆盖 |
| --- | --- |
| AI IDE | Cursor、Trae（含 CN 版）、CodeBuddy（含 CN 版）、Windsurf、Antigravity、Kiro、Qoder、ZCode |
| JetBrains 全家桶 | WebStorm、CLion、IntelliJ IDEA（含 CE）、PyCharm、GoLand、PhpStorm、RubyMine、Rider、DataGrip、DataSpell、RustRover、Aqua、Fleet |
| 其他 | VS Code / Insiders / VSCodium、Xcode、Android Studio、Zed、Sublime Text、Nova、BBEdit、TextMate、Emacs、MacVim、Neovide、Lapce、Eclipse、NetBeans、Qt Creator、HBuilderX、RStudio、Spyder、Visual Studio |

检测策略：**扫 `/Applications` 与 `~/Applications` 读取真实 bundle id**（沙盒内可读），命中不到再按 App 名字兜底（覆盖国内特供版、改名版、bundle id 未知的新 IDE），最后才退回 LaunchServices 查询；结果缓存 5 分钟并在扩展启动时预热。

设计理由：

- **打开类在上、创建类在下**：符合 macOS 原生右键「新建/粘贴放底部」的惯例。
- **不重复系统能力**：复制路径用系统自带的 `⌥⌘C`，复制文件本身用 `⌘C`，我们不做。
- **动态项只放在组末**：检测不到的编辑器整项消失，不会把别的项挤到别的行。
- **单层扁平**：嵌套子菜单（`新建 ▸`）在 FinderSync 里尚未验证，P0 不赌；验证通过后 P1 再收成两级。

### 5.2 不同上下文显示什么

> 统一规则：**目标目录 = 选中的文件夹本身 / 选中文件的父目录 / 空白处的当前目录**。三种情况都显示「新建」，不搞特例。

| 右键位置 | 显示 |
| --- | --- |
| 文件夹空白处 | 全部 4 项（新建建在该文件夹） |
| 选中 1 个或多个文件 | 在终端/编辑器中打开（父目录）+ 新建（父目录） |
| 选中文件夹（单个/多个） | 全部（新建建在该文件夹内；多选时建在第一个） |
| 混合选择（文件 + 文件夹） | 只显示打开类，避免「建到哪」歧义 |
| 侧边栏 / 工具栏 | 不显示 |
| 全屏空间（无桌面） | 无右键入口，属系统行为，不是 bug |

### 5.3 关键交互细节

- **不抢焦点**：新建成功**不**激活访达、**不**选中文件、**不**弹 App 窗口。
- **成功反馈（必须有）**：状态栏图标临时叠加 `checkmark.circle.fill`（约 1.2 秒淡出）+ HUD 显示「已新建：未命名 2.md」。HUD 为不抢焦点的 `NSPanel`（`.nonactivatingPanel`），停在状态栏下方约 2.5 秒。
- **失败反馈**：HUD 显示具体原因（见 §6 文案表）+「查看日志」；状态栏显示一次性橙色感叹号；`NSSound.beep()` 作为辅助，不作为主要反馈。
- **重名策略**：`未命名.md` → `未命名 2.md` → …；尝试 999 次仍失败则报「同名文件过多，未新建」。
- **减少动态**：系统开启「减弱动态效果」时，HUD 改为静态停留 1.5 秒、不做淡出动画。

### 5.4 新建文件面板（P0）

- 由主 App 弹出（因为扩展不能碰 `NSApp`），固定 484pt 宽，样式沿用 App 的玻璃质感。
- 布局自上而下：路径行（可点「选择…」换目录）→ 文件名输入框（默认 `未命名`，自动聚焦）→ 类型 3×2 网格按钮（Markdown / 文本 / JSON / Python / Shell / 自定义）→ 自定义后缀行（固定高度，仅在「自定义」时可编辑）→ 错误行（固定高度，避免跳版）→ 底部左侧实时预览「将创建 xxx.md」+ 右侧「取消 / 创建」。
- 回车 = 创建；`Esc` = 取消；文件名非法字符（`/`、`:`）自动过滤；输入为空时回退到 `未命名`。
- 记住上次选中的类型（下次打开预选）。
- 各类型写入内容：Markdown/文本 = 空；JSON = `{}\n`；Python = `#!/usr/bin/env python3\n\n`；Shell = `#!/bin/bash\n\n` + `chmod 755`。

## 7. 首次使用与安装体验

现状需要用户走 9 步，最容易卡在「从下载目录直接打开」（App Translocation 会让扩展注册失败）。文档必须写清，App 必须能自查。

1. 从 GitHub 下载 DMG → **拖进 `/Applications`**（README 必须加粗说明）。
2. 首次打开被 Gatekeeper 拦 → 系统设置「仍要打开」，或终端 `xattr -dr com.apple.quarantine`。
3. 打开 App → 设置页「集成」显示：**扩展未启用**。
4. 点「打开系统设置…」→ 勾选 ClipStats → 回 App 点「重新检测」→ 变「已启用」。
5. （可选）点「授权桌面 / 文稿 / 下载」提前触发 TCC，免得第一次右键时被拦住。
6. 右键验证。

**macOS 15（Sequoia）特例**：系统设置里没有访达扩展开关。
- 设置页提供按钮「启用扩展」：主 App 未沙盒，可直接 `Process` 调 `pluginkit -mAD` 拿到 UUID 再 `pluginkit -e use -u <UUID>`；
- 失败时回退为「拷贝命令」，并把命令填好 UUID；
- 附一行灰字：`macOS 15 移除了访达扩展开关，macOS 26 起恢复`。

## 9. 边界与异常

| 情况 | 期望行为 |
| --- | --- |
| 只读卷（DMG、只读外接盘） | 菜单**照常显示**「新建」（不在菜单构建时探测可写性，避免菜单长度抖动）；点击后精确报错 |
| 无写入权限目录 | 同上，点击后报「没有写入权限」 |
| 目标文件夹在点击瞬间被删 | 报「目标文件夹已被移动或删除」 |
| iCloud 占位文件 | 新建报「iCloud 文件尚未下载」 |
| exFAT / 网络卷不支持 chmod | 文件照建，额外提示「此磁盘不支持可执行权限」 |
| 同名过多 | 报错，不静默 |
| ClipStats 未运行 | 新建/打开类依赖冷启动唤起，**P0 不做兜底队列**，作为已知限制写进 README（P1 用请求队列补） |
| 扩展被系统禁用 | 设置页状态变灰，给出重新启用引导 |
| 全屏空间 | 无桌面可右键，属系统行为 |

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| ad-hoc 签名 + 未公证 | 用户过不了 Gatekeeper 就放弃 | README 三步走 + 源码构建方式 |
| macOS 15 无开关 | 用户以为坏了 | 设置页「启用扩展」直接调 pluginkit，失败再给命令 |
| TCC 首次授权 | 误判为 bug | 设置页提前授权 + HUD 报错带引导 |
| 常驻内存 | 与「轻量」定位冲突 | 开发前实测 `FinderSyncExt` 常驻内存并写进 README；超预算则不默认启用 |
| 系统大版本更新后扩展失效 | 功能静默消失 | 设置页状态检测 + 更新检查时提示 |
| 冷启动丢事件 | 未运行 App 时点新建无反应 | P0 写进已知限制；P1 用请求队列 |

## 13. 已确认的决策（2026-11-19）

| # | 决策 |
| --- | --- |
| 1 | 菜单根节点：**`ClipStats`** |
